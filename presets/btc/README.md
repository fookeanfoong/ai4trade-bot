# BTC EA preset（BTCScalper · XM BTCUSD#）

EA 源码：`mql5/BTCScalper.mq5`，回测/验证：`btc_research.py` → `reports/btc_research.md`
（每周一由 `.github/workflows/btc_research.yml` 重跑一次）。

## 有哪些 preset

| 文件 | 是什么 | 验证结果 |
|------|--------|---------|
| `default_validated.set` | H1 · 只开趋势回踩 · 1.5×ATR 止损 · RR1:1.5 · 时段过滤 | ✅ 样本外两边为正，但优势很薄：验证期 122 笔、胜率 50%、+0.078R |
| `m5_fast.set` | M5 · 回踩+突破 · 1.0×ATR 止损 · RR1:1.5 · 1 小时时间止损 | ❌ 两段全为负。$30 点差大约是 M5 ATR 的 40% |

## 整合了什么

| 来源 | 用了什么 |
|------|---------|
| 你的 `GoldScalper.mq5` | 按风险反推手数、硬性风险上限、点差过滤、当日熔断、分型结构、保本 + ATR 追踪、止损随单提交给服务器 |

| NyaoScalper（开源） | 死市过滤（ATR/均 ATR）、点差占 ATR 比例、反向长影线惩罚、RSI 甜区。**没有抄它的对冲链 / 马丁** |
| 网上常见 BTC 剥头皮 | EMA9/21 + 当日 VWAP 同侧、伦敦/纽约时段、时间止损 |

## 回测说明了什么（诚实版）

1. **真正的快进快出（M5/M15）在 XM 的点差下没有优势。** BTC 在 M5 上一根 K 线平均只走 $70~80，
   点差 $30 等于每笔先亏掉 0.4R。入场逻辑再好也补不回来。
2. **H1 趋势回踩 + 时段过滤**是唯一过关的组合。去掉时段过滤后期望值约等于 0，
   说明优势主要来自「只在伦敦/纽约时段做」。
3. 一共试了 48 组，其中 3 组过关，这有可能只是运气。要在新数据上继续过关才算数，
   所以工作流每周一会重跑一次。
4. 回测**没算隔夜利息**。XM 加密 CFD 的隔夜利息很贵，H1 的单最多拿 12 小时，可能跨过结算时间。

## 用之前先做这三件事

1. **看你账户的真实点差**：在 Market Watch 里右键 → Symbols → BTCUSD#，或者直接看 Ask−Bid。
   如果远大于 $30，结论只会更差。EA 里的 `InpMaxSpreadUSD` 要按实际点差来设。
2. **看本金够不够**：H1 的 ATR 约 $340，止损 1.5×ATR ≈ $500，最小 0.01 手的风险 ≈ $5。
   按 2% 的风险上限，**净值至少要 $250 左右**，否则 EA 会拒绝开仓（日志里会写原因）。
3. **先上模拟账户**，或者在 MT5 策略测试器里用 "Every tick based on real ticks" 跑一遍 BTCUSD#，
   至少攒 30~50 笔再考虑实盘。

## XM 的 BTC 是 24 小时的吗？

是，XM 的加密 CFD 是 **7×24**，周末也开，但周末可能有短暂维护，流动性差、点差大。
EA 周末照常交易，但风险减半（`InpWeekendRiskMult=0.5`），点差过滤器会挡掉点差特别大的时段。
不想周末交易就把 `InpTradeWeekend` 设为 `false`。

## 怎么加载

1. 把 `BTCScalper.mq5` 放进 MT5 的 `文件 → 打开数据文件夹 → MQL5 → Experts`，在 MetaEditor 里编译
2. 打开 BTCUSD# 图表（周期要和 preset 一致：validated 用 H1），把 EA 拖上去
3. 输入(Inputs) → 加载(Load) → 选这里的 `.set` 文件
4. 打开 Algo Trading

> 如果同一个账户上黄金 EA 也在跑，两个 EA 的 magic 号不同（20260809 / 20260930），互不干扰。
